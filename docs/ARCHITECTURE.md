## `scheduler/` file-ownership map

`scheduler/` is one Go `package main`.

**#1340 tuning page (`ui_server.go`, `static/ui/{tuning.html,app.js,styles.css}`):** `/tuning` is a dedicated read-and-launch workspace in the embedded dashboard bundle. It starts and polls #1339 runs, surfaces launch authentication failures locally, and re-reads `/api/strategies/<id>/config` when results are viewed so every patch is diffed against current effective parameters and a changed run baseline is visibly flagged. It never calls a config-write endpoint.

- `risk.go`/`strategy_interval.go` — `CheckRisk(*PlatformRiskAssist)` skips `manual`; `effectiveStrategyIntervalSeconds` accelerates checks in DD warn band (DD > `warn_threshold_pct`). **#1008** `forceCloseAllPositions` labels close legs via `classifyPositionTradeType` (HL/OKX perps + HL `manual` with `Multiplier=1` → `perps`; TopStep/CME → `futures`; `Multiplier=0` → `spot`) — operator-display only (`tradeLedgerDeltaSQL` ignores `trade_type`). **#1009** `closePositionIsCorrupt` (qty≤0 OR avgCost≤0) → `forceCloseAllPositions`/`bookPerpsCloseWithFillFee` (portfolio.go) clear with a **zero-PnL** `*_corrupt` leg (cash untouched) so booked PnL reconciles with the closed_positions row. **#1444 mark rails:** `collectPerpsMarkSymbols` feeds `type=perps` AND `type=manual` (manual keys off `sc.Symbol`, NOT `Args[1]` — the walker, the position map and the manual dispatch all read `sc.Symbol`, and a hand-written `args` list may name another coin; manual is hyperliquid-only at load, so a manual entry on any other platform contributes nothing and must never fall through to the OKX rail). Before it, manual belonged to NO rail (`collectPriceSymbols` filters `spot`, `collectFuturesMarkSymbols` filters `futures`+topstep), so a manual coin with no perps/hedge donor never entered `prices`, the per-cycle `mark` read `0.0`, and the `mark > 0` gates killed the HL trailing SL walker and the TP ratchet silently every cycle. `collectFuturesMarkSymbols` stays unchanged (relaxing it would be dead code). Side effect by design: manual coins now value at live mids in `PortfolioValue`, exposure and drawdown — same rationale as the #1159 hedge-coin block. **Regression tripwire:** the pure `collectMissingMarkPositions(strategies, openSymbols, prices)` runs once per cycle AFTER the strategy loop (perps publish their own mark inside it, so an init-time guard would warn spuriously) and `[WARN]`s per open position with no positive mark; only options strategies are excluded (their value comes from `OptionPositions`). Each entry carries `Live` (`isLiveArgs`), which picks the operator channel: a LIVE miss degrades auto-protective machinery so it also raises a throttled owner DM via `missingMarkAlerts` (`missing_mark_alerts.go`, keyed `(strategy_id, symbol)`, `alert_throttle_interval`, `Retain()` prunes recovered slots so a returning mark re-arms with no restart); a record-only miss is log-only but is still reported — `computeSubsetPortfolioValue` virtual-sums it and `sameAccountLiveManualMembers` folds in LIVE manual only, so a missing mark there silently reverts that strategy to `AvgCost` inside the kill switch's drawdown input. **Which mechanisms the alert may NAME is venue-scoped (#1445 review):** each entry also carries `Platform`/`Type` and a `DisabledManagers` list from the pure `markGatedManagers(sc)`, which returns the trailing-SL walker + TP ratchet for `hyperliquid` `perps`/`manual` and NOTHING otherwise — the OKX perps branch runs `runOKXCheck`/`runOKXExecuteOrder` and neither manager, and spot/TopStep futures run neither either, so the old unconditional text told an operator a stop-loss had stopped on a venue that never ran one. `formatMissingMarkDM` renders one bullet per named manager and always states the universal consequence (`PortfolioValue` falls back to entry cost, so the kill switch reads a stale valuation), which keeps a true claim on a venue with no managers. Keyed on type+venue rather than per-strategy close knobs on purpose: the knob-level gates are position-dependent (`effectiveTrailingStopPct` reads `pos.EntryATR`, and a post-TP `sl_after: trail_from_here` stamp arms the walker on a strategy configuring no trailing field), so a config-only test would UNDER-report a genuinely disabled protection. **One-shot valuation-basis peak migration (#1445 review):** `PortfolioRisk.PeakValue` is sticky and ratchet-up-only, so a peak accumulated while manual counted at `AvgCost` is not comparable to a live-priced total and could latch the kill switch — which force-closes the fleet BEFORE it latches — on the first post-upgrade cycle. Before `checkPortfolioRiskWithEquityAvailability`, and only while `PortfolioRisk.ManualMarkBasisRebaselined` is false AND `missingManualOnlyMarks(cfg.Strategies, riskOpenSymbols, prices)` is empty, the cycle recomputes the same total against `pricesWithoutSymbols(prices, manualOnlyMarkSymbols(cfg.Strategies))` (deletion, NOT zeroing — `PortfolioValue` falls back to `AvgCost` only on a MISSING key) and applies `manualMarkBasisPeakAdjustment`: `newPeak = oldPeak + (liveTotal - legacyTotal)`, the basis delta and nothing else. Drawdown is NOT zeroed and the peak is NOT set to the current total — a real drawdown accumulated under the old basis stays armed. `manualOnlyMarkSymbols` excludes any manual coin a perps/spot/hedge/futures rail already donated (its basis never moved). **The gate is the manual-only marks ALONE, never a complete mark set (#1445 review):** `computeSubsetPortfolioValue` is additive over `PortfolioValue` plus price-independent real wallet balances, so only positions held under a manual-only coin can move the delta — a missing spot/OKX-perps/futures mark is absent from BOTH maps, falls back to `AvgCost` in both, and cancels exactly. Gating on it would defer the migration for the length of an unrelated outage, leaving an underwater manual position live-priced in `totalPV` against a cost-basis peak: the very spurious first-cycle fire the migration exists to prevent. `missingManualOnlyMarks` walks the OPEN-position map (not the configs), so a flat manual coin never stalls the migration and a manual-only coin held by any strategy still gates it. The latch is persisted (`portfolio_risk.manual_mark_basis_rebaselined`) so a restart cannot re-run it; it is stamped whenever the measurement ran, even when no adjustment was needed. Emits a `basis_rebaseline` `kill_switch_events` row plus one owner DM. **#1448 portfolio latch ownership:** `checkPortfolioRiskWithEquityAvailability` computes both drawdown lenses as before, but only ONE can latch on a cycle. `equityGuardArmed := equityAvailable && prs.PeakValue > 0` (evaluated AFTER the peak ratchet, so any cycle with a positive `totalValue` arms it in the same call); armed ⇒ the latch trips on `equityDD > MaxDrawdownPct` ONLY and `Source` is always `"equity"`; not armed ⇒ it trips on `marginDD > MaxDrawdownPct` and `Source` is always `"margin"`. `PeakValue == 0` is folded into "not armed" deliberately rather than kept as a third case: it means no equity snapshot has EVER been recorded, which is the same "the equity guard cannot measure" condition as a pooled wallet with no trustworthy balance, and it preserves cold-start protection verbatim. The margin-wins tie-break is gone — the two arms are mutually exclusive, so no tie can exist. **Why:** the latch force-closes the whole book (including `manual` and spot positions that contribute nothing to the margin ratio, `AggregatePerpsMarginInputs` counts `type == "perps"` only) and holds it until an operator resets, while the two signals diverge exactly when deployed margin is a SMALL share of the book — there the avertable loss is bounded by that small margin and the latch cost is the full book. Live incident 2026-08-22: 65.3% margin drawdown on $48.42 of margin latched the fleet at 9.8% equity drawdown against a 30% limit, closing an ETH position still above its configured SL floor and a flat-PnL manual BTC position. Per-POSITION margin protection is unchanged and stays with the #292 per-strategy circuit breaker in `CheckRisk` (same ratio, force-closes that one strategy on a cooldown, no latch). **Warn band:** structurally unchanged (`marginWarn = marginDD > warnDrawdownPct`, `source="margin"` event labeling, all `WarningSent`/`WarnBandEnteredAt`/`LastWarning*DDPct`/`Warning*DeltaPct` bookkeeping identical), except that `marginDD` above `MaxDrawdownPct` is now a REACHABLE warn state and gets its own reason wording — "exceeds limit … portfolio latch governed by equity drawdown … per-strategy circuit breakers own margin protection (#1448)" instead of the false "approaching". `BuildPortfolioWarningMessage` renders the margin figure as `perps margin X% from limit`, no longer as a distance to the kill switch, because the warn DM never renders the reason string and that label was the only operator-facing text on this path (**#1449 review** made that label conditional — see `EquityGuardArmed` below). **#1449 review — untrusted equity is a THIRD state, not "unavailable":** `pooledEquityComplete` says the total EXISTS; it does not say it is trustworthy. `computeSubsetPortfolioValue` sets `usedPVFallback` when a fully-contained NON-pooled shared wallet's balance fetch fails and the total substitutes `sum(member PV)`, and `resolveSharedWalletRiskBalances` sets `usedStale` for a one-generation-old balance — both leave `pooledEquityComplete == true`. The call site now also passes `equityTrusted = pooledEquityComplete && !usedPVFallback && !usedStaleRiskBalance`. The latch **stays with equity** on those cycles by design: `sum(member PV)` prices every position at the same live marks and a one-generation-old balance is a real balance, so equity still measures real book loss — and handing the whole book to the margin signal over a transient balance-fetch blip is precisely the #1448 failure. What an untrusted total must never do is make a drawdown DISAPPEAR, so two things gate on `equityTrusted` instead: (1) the peak ratchet is skipped inside the risk check (the caller's post-hoc rollback stays as belt-and-braces, but `CurrentDrawdownPct` is no longer written off a peak the caller is about to undo), and (2) `equityDD` is FLOORED at `priorEquityDD` (the `CurrentDrawdownPct` read before anything this cycle overwrites it). Monotone across a run of untrusted cycles; the first trusted cycle overwrites with a real measurement. **The floor can never itself latch**, because `priorEquityDD` is CLAMPED to `cfg.MaxDrawdownPct` while the latch test is a strict `>`. The clamp is load-bearing and replaces an earlier, WRONG soundness argument ("every stored reading came from a cycle that did not latch, so it is at or below the limit"): `CurrentDrawdownPct` is written BEFORE the latch check, so the latching cycle persists its OVER-LIMIT measurement and `db.go` writes it to SQLite. Both auto-reset paths cleared it, but the #1368 owner-DM reset cleared only `KillSwitchActive`/`KillSwitchAt`, so the first post-reset untrusted cycle floored a healthy measurement back up to the stale over-limit value and re-latched the whole book off a number nothing measured that cycle (a plain restart reaches the same state). The clamp is applied at READ time, never stored, so a `MaxDrawdownPct` change re-derives it instead of truncating the record; a non-positive limit yields a non-positive floor, which cannot raise a drawdown already floored at 0. A genuine this-cycle measurement above the limit is NOT clamped and still latches, so the clamp is not a fail-open. `ResetPortfolioKillSwitchManual` (risk.go) is the second half of the fix and the sole body of the DM reset: it clears both drawdown readings and the substituted marker alongside the latch flags — matching `ClearLatchedKillSwitchSharedWallet` and `AutoResetConfirmedFlatKillSwitch` — and RETURNS the pre-reset reading so the `reset` audit event still records it. It deliberately does NOT re-baseline `PeakValue`: a manual reset makes no claim that the book is flat or the total verified. **#1449 review — the floored reading is persisted and therefore MARKED:** `CurrentDrawdownPct` carries the floored decision value rather than the raw quotient, so the stored number always equals the one that cycle's latch and warn band decided on. That breaks the type's arithmetic invariant (`(PeakValue, CurrentDrawdownPct)` reconstructable) on exactly those cycles, so `PortfolioRiskState.DrawdownReadingSubstituted` (persisted, `portfolio_risk.drawdown_reading_substituted`) marks them and EVERY operator surface printing the percentage beside the dollar figures must label it — otherwise the percentage and the two dollar amounts silently stop reconciling during exactly the incident a post-mortem would reconstruct. A trusted cycle always writes the exact measurement and clears the marker. Sizing is **qty-event, not price**: `hedge_qty = primary_qty_delta × primary_px × ratio / hedge_px`, so mark drift never re-trades the leg; a REDUCE takes the same FRACTION off the HELD hedge qty (immune to mark movement between open and reduce). **Fail-closed everywhere:** unusable marks or an unknown primary side return `Blocked` (never size off a stale price); an exchange failure never mutates virtual state (`hedgeExecuteConfirmed`/`hedgeCloseConfirmed`); `hedgeOrderSkipReason` re-checks preconditions against a FRESH snapshot immediately before spawning (skip-reason mirror rule). **Partial fills always book the exchange's reported size and advance the watermark PROPORTIONALLY** — opens/adds scale the basis delta by `filled/requested`, reduces and short-filled closes interpolate via `hedgeReducedBasis(oldBasis, target, filled, requested)` (or `hedgeBasisAfterPartialReduce(oldBasis, preQty, remainingQty)` where only held sizes are available — the manual pending-action drain and reconcile; both derivations agree), and a short-filled full close books a PARTIAL close rather than marking the leg flat. `forceCloseCoupledHedgeLeg` queues `IsFullClose` off the ACTUAL drain, never the operator's primary-close intent — a short fill booked as full would delete the leg's `HedgeFor` stamp while inverse exposure remained on-chain, and neither `runHedgeSync` (primary-flat + no leg → none) nor reconcile (refuses to adopt an unstamped position) could recover it. **An externally REDUCED hedge is re-grown:** a downward reconcile resync shrinks the basis by the same fraction the leg lost, so the decision core sees a real delta and adds back — the delta math never reads the hedge's own size, so without this a partial liquidation would silently run under-hedged forever while a FULL external close already got re-opened. Deliberately one-directional: an upward resync leaves the basis alone (unowned surplus is not ours to trade). Stamping the full target on a partial would leave the pair over-hedged (net-biased past neutral) while `hedgeTargetDecision` reports `delta==0`, and nothing would ever revisit it since mark drift deliberately does not re-trade the hedge. **Constraint-4 unwind:** a hedge failure on a cycle that ADDED primary exposure (`hedgeSyncInputs.FreshExposureQty>0`) closes exactly that increment reduce-only via `unwindPrimaryAfterHedgeOpenFailure` + CRITICAL owner DM — a fresh open unwinds fully (cancelling its resting OIDs), a failed scale-in add unwinds only the add (the pre-add position is still hedged; protection is preserved). A failure on any LATER cycle alerts and retries instead of liquidating an aged position; a failed unwind needs no latch — the reconciler self-heals next cycle. Dust guards: sub-`hedgeMinOrderNotionalUSD` ($10) adds/reduces defer WITHOUT advancing the basis (shortfall accumulates); a reduce leaving sub-minimum residue collapses into a full close. Ownership is **only** `Position.HedgeFor` (+`HedgePrimaryQtyBasis`), both persisted — never coin→config inference (constraint 5); an unstamped position on the hedge coin is never adopted. **Collision matrix (`validateHedgeConfigs`, config.go)** rejects hedge coin == own primary, == ANY configured strategy's coin (perps+manual, live+paper), or == another hedger's hedge coin, plus `direction:"both"`, non-HL-perps owners, and out-of-vocabulary/bounds fields; a DISABLED block is shape-checked but exempt from collisions. The review job omits `id-token: write` specifically because, with it present, injected code reachable during a review run could mint the Claude App token via OIDC.
- **Mode routing (#1334):** the `@claude` keyword match skips an optional `opus`/`sonnet`/`fable` shorthand token before checking the route keyword. `fix-pr` performs in-place review-reconciliation: fetch all unaddressed review feedback, validate each finding, fix what survives, fold the triggering comment's text in as extra scope, post a disposition comment, and trigger a fresh re-review. The retired `fix` keyword is no longer special — it now behaves as an ordinary `fix-pr` comment. `docs-sync`/`create-release` flows are wired into the router but gated off by the `DOCS_RELEASE_ENABLED` repo variable until enabled.
- **`claude_args` allowlist:** no interpreters/`go`/`uv run` are on the allowlist, no Python env is installed (the `setup-go` step stays only so `gofmt` works), and every prompt file restates the no-execution ban independently. `gh api` is dropped from the allowlist entirely (not merely restricted).
- **Update script (`scripts/update.sh --restart`):** DBs are guarded against the rsync path clobbering them via `*.db`/`*.db-wal`/`*.db-shm`/`*.db.lock` globs (also `.git/`/config/venv/binary are protected). Env knobs: `STATUS_PORT`, `ACTIVE_TIMEOUT=30s`, `HEALTH_TIMEOUT=60s`. Restart mode defaults to `--restart-mode systemd` and falls back to `signal` (`GO_TRADER_PIDFILE`/`GO_TRADER_RUN_SH`) when systemd isn't available. Batch mode's `--update-all-root`/`GO_TRADER_UPDATE_ALL_ROOT` pins the legacy glob/no-systemd fallback for layouts `discover_deployment_dirs_from_systemd` can't see; a zero-update batch run hard-fails rather than silently no-op'ing. `discover_deployment_dirs_from_systemd` finds deployments from the `WorkingDirectory` of `go-trader`/`go-trader-*`/`go-trader@*` systemd units. **#1461** `--all` per-dir unit resolution: `discover_deployment_unit_map` builds a canonical-dir → unit map from the same active-unit set; each child that owns a per-dir unit overrides the parent's `service_unit` (parent `--unit`/`--service` stripped from the child's argv) and restarts under the right unit. Dirs no active unit owns fall back to the parent's `service_unit` and log a warning.
- **Testing — pytest ordering:** the registry/sys.path tests need the FULL suite run together because isolated runs mask open-vs-close `registry.py` import-order conflicts that only surface when both registries get imported in the same process. **#1304** CI runs pytest with `-n auto` (pytest-xdist), which makes per-worker import order nondeterministic — this is why an ambiguous bare `import` of a same-named test module is unsafe (load by path via `importlib.util.spec_from_file_location` instead) and why an intermittent CI pytest failure should be treated as a test-isolation bug to fix, never a flake to re-run.
- **Testing — ATR close evaluators:** `ensure_atr_indicator` must run before the evaluator loop for `Position.EntryATR`-dependent evaluators. **Tiered-TP dust:** the sole-peer final tier closes via `market_close(sz=None)`; `compute_tp_tier_sizes` pre-floors the non-final tiers so rounding dust doesn't accumulate there instead. `avwap_stop` reads a **live re-anchored** `market["avwap"]` (there is no `Position`-carried anchor, unlike the ATR evaluators) — it is a **virtual exit only**, deliberately absent from `isTieredTPATRCloseName`/`closeStrategiesSuppressedByOnChainProtection`; `evaluate_open_close`/`Backtester` each warn once when the strategy is configured with `avwap_stop` but no usable `avwap` column is ever injected into the frame.
