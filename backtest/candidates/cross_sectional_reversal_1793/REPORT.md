## Baselines

- `cross_sectional_momentum`: the registered #1787 basket evaluator called by the study on the same closed-bar input the runner gives the candidate: for every member, the last lookback_bars (60) closed daily bars ending with the bar that closes at the deadline, the frozen allocation context of this basket, and the training-selected return lookback, volatility lookback and quantile of the candidate; its exact weights become frozen baseline weights for that deadline. Parameters {'quantile': 0.2, 'return_lookback_bars': 14, 'volatility_lookback_bars': 28}. 70 deadlines carry frozen weights, 70 of them a nonzero target; 0 hold the whole set ([]).
- `mean_reversion_pro`: the registered single-member evaluator with its frozen registered parameters, run separately for every eligible member on the last 200 closed daily bars ending with the bar that closes at the deadline; only the entry signal of that last bar is read: target weight = signal / N for N eligible members (+1 long entry, -1 short entry). The signal is never read as a position: Python keeps no state between deadlines, a zero signal sets a zero target, and unused allocation is never renormalized. Parameters {'adx_max': 25.0, 'adx_period': 14, 'confirm_window': 3, 'entry_std': 2.0, 'lookback': 30, 'rsi_overbought': 70.0, 'rsi_oversold': 30.0, 'rsi_period': 14, 'touch_entry': 0, 'turn_entry': 0}. 70 deadlines carry frozen weights, 0 of them a nonzero target; 0 hold the whole set ([]).
- every arm runs through the same replay with the same members, member capital, member close policy, costs, gross budget, per-coin cap, net bound (max_transition_net_usd 2500, never relaxed), decision deadlines, windows and the training-selected holding horizon; only target_input differs (baselines use the #1791 baseline target-input path). Python produces frozen deadline weights only; Go applies listing eligibility, the gross, net and per-coin checks (a weight set outside them holds the whole set), position lifetime, expiry, action ordering and recovery. A flat member keeps its own cash, which never moves to another member. The study checks that the adapter froze exactly the converted weights at every deadline it did not hold.

## Limits

- Execution surfaces not modeled: maker fills, a separate spread (spread sits inside slippage), order-book depth and market impact, intrabar execution, venue outages and partial venue fills (every scripted fill is a full taker fill at the step mark plus slippage), and historical changes of szDecimals or minimum order size (lot metadata is read once at preparation).
- Proxy-price basis: marks are the open of the daily Hyperliquid bar at each step; the venue's mark and oracle prices, which drive funding and liquidation, can differ from candle prices. Funding is charged from the venue's hourly rates at the sampled step mark.
- Members hold separate paper cash; idle cash earns nothing. Returns are stated on the gross budget, and the summed member capital is larger than the gross budget.
- The candidate's target net weight is exactly 0, but a dollar-neutral basket is not beta neutral, and transitions pass through states bounded by the net allowance. The mean_reversion_pro baseline can be directional within the same net bound.
- The universe is a fixed set of surviving large coins chosen by a frozen rule; the result does not cover delisted coins, new listings or a larger universe.
- The windows were inspected by #1792 before this protocol; the held-out comparison is retrospective.
- A study pass would grant no live admission; the basket live refusal stays in force for every outcome.
